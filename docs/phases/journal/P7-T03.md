## Plan (Gate 1)

### Scope
Build `MedalsByMemberReport` service returning per-member medal counts (GOLD/SILVER/BRONZE/MERIT/total) ordered by total descending, limited to top-N. Wire it to a new `GET /api/v1/reports/medals-by-member` endpoint.

- `database-schema` participations → `{id, event_id, member_id, session_id}` confirmed
- SQL pivot strategy: `SUM(CASE WHEN medal_type = 'GOLD' THEN 1 ELSE 0 END)` — single-pass GROUP BY member, avoids PHP pivot
- `DB::raw` + `->when()` pattern same as P7-T02

### Schema / endpoints / pages
No migrations.

**`GET /api/v1/reports/medals-by-member`** → `v1.reports.medals-by-member`  
Query params: `session_id`, `sport_id`, `unit_id`, `tier_id`, `limit` (1-500, default 50)

Response:
```json
{
  "data": [{"member": {"id": 1, "member_code": "...", "full_name_hi": "...", "full_name_en": "..."}, "GOLD": 3, "SILVER": 1, "BRONZE": 0, "MERIT": 0, "total": 4}],
  "filters": {"session_id": null, "sport_id": null, "unit_id": null, "tier_id": null},
  "limit": 50
}
```

### Risk + mitigation
- **Risk:** `LIMIT` in `DB::table()` — ensure `->limit()` is used, not raw.  
  **Mitigation:** Builder `->limit($limit)` is safe (integer-cast in service signature).

### Test plan
- Pest Feature (service): empty; single member GOLD count; limit truncates; unit_id filter; org isolation; session_id filter
- Pest Feature (API): 401 unauthenticated; 403 no permission; 200 valid; limit param respected; limit=0 → 422

### Decisions
- **`SportSession` object vs ID in test helper:** `::find()` fails under the `BelongsToOrganization` global scope in test context (no authenticated user). Switched helper to accept the model instance directly.
- **`limit` not in shared trait:** adding it to `HasReportFilters` would pollute `MedalsPivotController`'s response. Handled in `MedalsByMemberRequest` + controller only.
