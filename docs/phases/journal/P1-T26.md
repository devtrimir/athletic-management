### Key implementation notes
- **Slug**: auto-generated server-side via `Str::slug($data['name_en'])` in controller; NOT a user-visible form field
- **Category**: `<Select>` from shadcn/ui with options INDIVIDUAL, TEAM, COMBAT, WATER; rendered as `<select name="category">` in the `<Form>` render-prop
- **Route param**: `{sport}` (singular of "sports"); controller methods use `Sport $sport`
- **UpdateSportRequest**: `$this->route('sport')->id`
- **No DB transaction**: no `is_current` flag, no single-item uniqueness to enforce beyond the DB constraint
- **No `BelongsToOrganization` global scope yet** → manual `->where('organization_id', ...)` in controller index
- **Ordering**: `->orderBy('name_en')` in index

### Risk + mitigation
- **Risk:** `fake()->unique()` in SportFactory exhausts 8 options at ~8 records; tests creating multiple sports may conflict.
  **Mitigation:** Use `Sport::factory()->make()` manually with explicit distinct values in beforeEach, or use `sequence()`.

### What changed

- `app/Http/Requests/Settings/UpdateSportRequest.php` — same + `->ignore($sportId)` on name_en unique

- `routes/settings.php` — added `Route::resource('settings/sports', SportController::class)->except(['show'])->names('sports')`
- `resources/js/pages/settings/sports/index.tsx` — table: name_hi, name_en, category; edit/delete actions
- `resources/js/pages/settings/sports/create.tsx` — bilingual inputs + shadcn `<Select>` for category
- `resources/js/pages/settings/sports/edit.tsx` — pre-filled form with `setLayoutProps` dynamic breadcrumbs
- `tests/Feature/Settings/SportCrudTest.php` — 17 tests: happy path, required validation, enum validation, 403 no-permission, 403 cross-org (regular user)

### Decisions
- **Unique check on `name_en` column (not `slug`):** slug collision from different `name_en` values is a rare edge case; validating on `name_en` gives a clear user-facing error without a custom validator.
- **`slug` not editable:** generated server-side only from `name_en` via `Str::slug()`; no form field exposed to avoid sync issues.
- **No DB transaction:** unlike Sessions (which had `is_current` single-flag logic), Sports have no such constraint.
