## Plan (Gate 1)

### Scope
Resolve PNO conflict on re-adding soft-deleted members through a Hybrid Restore & Re-creation architecture.
When a user inputs a PNO belonging to a soft-deleted member on the Add Member form, detect the archived profile and offer a 1-click "Restore Member" option (retaining tournament medals, rosters, and career history), while also allowing authorized users to permanently purge zero-connection records or create a fresh member under a database-level partial unique index (`WHERE deleted_at IS NULL`). In addition, expose an "Archived / Deleted" status scope in the Members listing with a direct Restore action.

### Risk + mitigation
- **Risk:** Creating a new member with the same PNO as a soft-deleted member leaves two records in the DB with the same PNO (one active, one archived). If someone later tries to restore the archived member, a collision occurs.
  **Mitigation:** `MemberController@restore` explicitly validates that no active member or coach in the organization is currently using the PNO before executing `restore()`, returning a clear 422/error toast if a collision exists.
- **Risk:** Force-purging an archived member with historical medals or participations leaves orphaned foreign keys.
  **Mitigation:** `forceDestroy()` delegates to `MemberDeletionService::getImpact()` and rejects force deletion if any historical or active connections exist, allowing purge only for clean/zero-connection records.

### Test plan
- Pest Feature (`tests/Feature/MemberRestoreTest.php`):
  - Unauthorized user without `members.restore` cannot restore a member (403).
  - PNO check endpoint accurately reports active conflict, deleted member profile, or available.
  - Partial unique index allows creating a new active member when a soft-deleted member shares the PNO.
  - Restoring a soft-deleted member reactivates status to `ACTIVE`, creates status history entry, and logs audit.
  - Restoring fails with validation error if an active member currently holds the PNO.
  - Permanently purging a zero-connection soft-deleted member deletes it from the database entirely.
  - Permanently purging a member with historical connections is rejected.
  - Member index filters by `'status_scope' => 'archived'` and lists soft-deleted members.

## Implementation (Gate 2)

### Changes Made

1. **Database Migration (`database/migrations/2026_09_10_172815_update_pno_unique_index_on_members_table.php`)**:
   - Replaced plain compound unique index `members_organization_id_pno_unique` with partial unique index `CREATE UNIQUE INDEX members_organization_id_pno_unique ON members (organization_id, pno) WHERE deleted_at IS NULL`.
   - Migration and rollback both tested cleanly.

2. **Validation Rule (`app/Rules/UniquePnoAcrossPeople.php`)**:
   - Added `whereNull('deleted_at')` to `members`, `coaches`, and `incharges` lookup queries so soft-deleted records do not trigger active unique collisions during new record validation.

3. **Backend Service & Controller Architecture**:
   - Extracted domain operations into [`app/Services/Members/MemberDeletionService.php`](app/Services/Members/MemberDeletionService.php):
     - `checkPno(string $pno, int $organizationId): array` — checks active collisions, soft-deleted member existence, and historical impact summary.
     - `restore(Member $member, ?User $actor = null): void` — atomically validates against active PNO collisions, restores member, activates status, writes `member_status_history`, and logs audit trail.
     - `forceDelete(Member $member, ?User $actor = null): void` — enforces zero-connection guard and permanently purges clean records.
   - [`app/Http/Controllers/MemberController.php`](app/Http/Controllers/MemberController.php): Kept thin and focused on HTTP transport, delegating business logic to `MemberDeletionService`.
   - Updated `app/Policies/MemberPolicy.php`:
     - Added `forceDelete()` delegating to `members.delete`.
     - Updated `restore()` to authorize users with `members.restore`, `members.delete`, or `members.update`.

4. **Routes & Wayfinder**:
   - Registered `GET members/check-pno`, `POST members/{member}/restore` (`withTrashed`), `DELETE members/{member}/force` (`withTrashed`), and `Route::resource('members')->withTrashed(['show'])`.
   - Restored missing `imports.errors` route in `routes/web.php`.
   - Regenerated TypeScript Wayfinder actions and route helpers via `php artisan wayfinder:generate --with-form --no-interaction`.

5. **Frontend Modular UI Architecture**:
   - [`resources/js/components/members/archived-member-action-dialog.tsx`](resources/js/components/members/archived-member-action-dialog.tsx): Dedicated, single-purpose modal for archived members. Displays preserved historical records (participations, medals, recognitions, promotions), blocks purge with an informative alert if connections exist, requires typed PNO/code confirmation if safe to purge, and provides a direct Restore action.
   - [`resources/js/components/members/delete-member-dialog.tsx`](resources/js/components/members/delete-member-dialog.tsx): Dedicated exclusively to active member soft-deletion (single responsibility principle).
   - [`resources/js/components/members/pno-conflict-notice.tsx`](resources/js/components/members/pno-conflict-notice.tsx): Reusable component encapsulating live debounced PNO lookup, active conflict warning, and archived member alert with quick restore and `<ArchivedMemberActionDialog>` integration.
   - [`resources/js/pages/members/create.tsx`](resources/js/pages/members/create.tsx): Replaced 100+ lines of inline states/JSX with `<PnoConflictNotice />`.
   - [`resources/js/pages/members/index.tsx`](resources/js/pages/members/index.tsx): Integrated `<ArchivedMemberActionDialog>` when clicking the delete icon for archived members in the listing table, and removed the "Quick info" button for archived members.

   - [`resources/js/pages/teams/show.tsx`](resources/js/pages/teams/show.tsx): Guarded quick view trigger so soft-deleted/archived members do not show quick info.
   - Context-Aware Back Navigation & Breadcrumbs: Updated [`resources/js/pages/members/show.tsx`](resources/js/pages/members/show.tsx) and [`resources/js/pages/members/index.tsx`](resources/js/pages/members/index.tsx) so navigation preserves `status_scope`.
