## Summary (Gate 3)

### What changed
- `config/rbac.php` — 18 permission codes across 8 groups (members, coaches, teams, tournaments, imports, reports, settings, reference_data). Each entry has `code`, `group`, `name_hi`, `name_en`.
- `app/Console/Commands/RbacSync.php` — reads catalog, calls `Permission::upsert()` with `uniqueBy: ['code']`, updates group/name fields, flushes the Redis cache, outputs a count line.
- `tests/Feature/RbacSyncCommandTest.php` — 3 tests, 8 assertions.

### Decisions
- **`Cache::flush()` after upsert:** The Rbac service caches per-user permissions. After a sync (e.g., permission renamed or regrouped) stale caches would serve wrong data. Full flush is safe at deploy time; at runtime `Rbac::invalidate()` is granular enough.
- **Never deletes rows:** Removing a code from the config does not remove it from the DB. Intentional — orphaned rows are harmless (no roles assigned to them), and accidental deletes would break in-flight requests.
- **`#[Signature('rbac:sync')]`:** Standard short-form registered globally; consistent with Laravel's built-in `migrate`, `horizon:publish` etc.
