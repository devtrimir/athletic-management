**P2B-T03 — `MemberPhotoController`**
- `POST members/{member}/photo` — MIME jpeg/png/webp, max 2 MB, store to `public/member-photos/{org_id}/`, delete old file on replacement

- Form Requests: StoreLegacyAchievementRequest, UpdateLegacyAchievementRequest, StoreAchievementBenefitRequest, UpdateAchievementBenefitRequest
- Morph map in `AppServiceProvider`: `member_legacy_achievement` + `achievement`
- Route additions in `routes/web.php`

## Summary (Gate 3)

### What changed
- **StoreMemberRequest + UpdateMemberRequest**: 9 new profile field rules added (`blood_group`, `caste`, `promotion_date`, `appointment`, `home_address`, `recruitment_type`, `sport_event`, `other_notes`, `team_since`) with appropriate `Rule::in` and `nullable` constraints; `UpdateMemberRequest` wraps all new rules in `sometimes`
- **StoreMemberPhotoRequest**: new — MIME jpeg/png/webp, max 2 MB
- **MemberPhotoController**: `store()` + `destroy()` — uploads to `public/member-photos/{org_id}/`, deletes old file on replacement/removal; auth via `Gate::authorize('update', $member)`
- **StoreLegacyAchievementRequest + UpdateLegacyAchievementRequest**: new — full enum validation for `period`, `level`, `medal_type`; `UpdateLegacyAchievementRequest` wraps all in `sometimes`
- **MemberLegacyAchievementController**: `store()` / `update()` / `destroy()` scoped to member; `abort_if` ownership check; auth via `manageLegacyAchievements` policy
- **StoreAchievementBenefitRequest + UpdateAchievementBenefitRequest**: new — polymorphic `benefitable_type` locked to `['member_legacy_achievement']` for now
- **AchievementBenefitController**: `store()` resolves morph map → parent → member; `update()` + `destroy()` load benefit and re-authorize via `manageBenefits` policy
- **routes/web.php**: 8 new routes (photo store/destroy, legacy-achievements store/update/destroy, achievement-benefits store/update/destroy)
- **AppServiceProvider**: morph map registered in `configureMorphMap()` — `member_legacy_achievement` + `achievement`
- **All 29 form requests in app/Http/Requests/**: pre-existing PHPDoc annotation `list<ValidationRule|string>` → `array<string, mixed>` (PHPStan level 6 compliance fix, pre-existing issue now surfaced); unused `ValidationRule` imports removed by Pint

### Decisions
- Photo endpoint uses `Gate::authorize('update', $member)` rather than a separate permission — photo is part of profile update
- `AchievementBenefitController@store` accepts only `member_legacy_achievement` as `benefitable_type` in this PR; `achievement` wired in PR 3
- `resolveMember()` is a private helper — will grow when live achievement support is added in PR 3
