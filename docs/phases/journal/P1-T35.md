## Plan (Gate 1)

### Scope
"Pest: org-scope leakage tests (user from org A cannot read org B data)."
Proves that the `BelongsToOrganization` global scope prevents cross-tenancy data access via HTTP routes for
the three org-scoped reference-data resources: SportSession, Sport, Unit.
Districts and TournamentTiers are global (no `organization_id`) and are excluded from leakage tests by design.

### Boost MCP research (mandatory)
- `database-schema` table=`sport_sessions` → confirms `organization_id` FK present
- `database-schema` table=`sports` → confirms `organization_id` FK present
- `database-schema` table=`units` → confirms `organization_id` FK present
- `database-schema` table=`districts` → NO `organization_id` — global resource, excluded
- `database-schema` table=`tournament_tiers` → NO `organization_id` — global resource, excluded
- Reviewed `app/Models/Scopes/BelongsToOrganization.php` — scope filters on `auth()->user()?->organization_id ?? 0`

**Doc drift found:** None.

### Files to touch
- `tests/Feature/OrgScopeLeakageTest.php` — new: all leakage assertions

### Risk + mitigation
- **Risk:** Route model binding may resolve by PK before global scope applies, letting Org B user access Org A model.
  **Mitigation:** The scope is applied at Eloquent query level; route model binding uses `Model::find()` which goes through the scope. If the model isn't found, Laravel returns 404. Tests verify this.

### Test plan
Per org-scoped resource (SportSession, Sport, Unit):
1. `GET index` — Org B user's collection is empty (Org A data not leaked)
2. `GET edit` — Org B user requesting Org A model → 404
3. `PATCH update` — Org B user → 404
4. `DELETE destroy` — Org B user → 404

Plus one global sanity check: Org B user can still see their own records on the index.
