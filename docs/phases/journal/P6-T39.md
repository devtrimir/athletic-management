### Risk + mitigation
- **Risk:** playing achievements accidentally feed medal tallies. **Mitigation:** separate table, no relations to achievements/participations; test asserts `Achievement` count unchanged after store.
- **Risk:** promotions reward-evidence (`rewardEvidenceOptionsPayload`) picking up playing records. **Mitigation:** keep separate payload key; evidence query untouched.
- **Risk:** dev DB reset. **Mitigation:** never migrate/seed/rollback dev DB (pgsql `uppscb1`); tests use sqlite :memory:.
