## Plan (Gate 1)

### Scope
Session-based locale switching. `SetLocale` middleware reads `session('locale', 'hi')` and calls `app()->setLocale()`. `POST /locale` validates `hi|en`, writes to session, redirects back (Inertia calls with `preserveState: true, preserveScroll: true` for zero-reload UX). Locale shared to React via `HandleInertiaRequests`. No URL prefix on routes.

## Summary (Gate 3)

### What changed
- `app/Http/Middleware/SetLocale.php` — reads `session('locale', 'hi')`, calls `app()->setLocale()`
- `app/Http/Requests/UpdateLocaleRequest.php` — `authorize: true`, `locale: required|in:hi,en`
- `app/Http/Controllers/LocaleController.php` — `update()` writes validated locale to session, returns `redirect()->back()`
- `app/Http/Middleware/HandleInertiaRequests.php` — added `'locale' => fn () => session('locale', 'hi')` lazy shared prop
- `routes/web.php` — added `Route::post('/locale', [LocaleController::class, 'update'])->name('locale.update')`
- `bootstrap/app.php` — `SetLocale::class` inserted before `HandleInertiaRequests` in the web append stack
- `tests/Feature/LocaleTest.php` — 4 passing assertions (7 assertions total)

### Decisions
- **Session over URL prefix:** URL prefix approach was removed per product decision; session is simpler and avoids retrofitting every future route.
- **No auth gate on POST /locale:** Locale switching is valid for guests too. UI visibility (admin-controlled) will be enforced in P1 via `permission:` middleware check in the component.
- **Form Request over inline validation:** Project rule — no controller-level validation.
- **`SetLocale` before `HandleInertiaRequests`:** Ensures `app()->getLocale()` is set before shared props are computed (though `locale` shared prop is lazy, this ordering is safer for any server-side translation use).
