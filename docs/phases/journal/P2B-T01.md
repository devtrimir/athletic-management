## Plan (Gate 1)

### Scope
Add 10 profile columns to `members`, create `member_legacy_achievements` (unified pre/post-recruitment history table), create `achievement_benefits` (polymorphic benefits ledger covering both legacy and live achievements). Update models, factories, MemberResource, and RBAC config. Zero frontend changes in this PR.

### Boost MCP research
- `search-docs` packages=[LARAVEL] queries=["alter table add columns migration", "enum column migration"] → Use `Schema::table` + `$table->after()` for column ordering; `$table->enum()` for MySQL ENUM types.
- `search-docs` packages=[LARAVEL] queries=["polymorphic relationship morphTo morphMany"] → `morphTo()` / `morphMany()` standard; use `constrained()` not available for morph FKs — use manual index.
- `database-query` `DESCRIBE members` → confirmed 21 columns, none of the 10 new fields exist.
- `database-query` `SHOW TABLES` → confirmed `member_legacy_achievements` and `achievement_benefits` do not exist.
- Skills consulted: `laravel-best-practices`

**Doc drift found:** `config/rbac.php` missing `members.changeStatus`, `members.restore`, `members.manageAlias` that MemberPolicy already references. Adding new permissions for legacy/benefits in this task; the missing three are pre-existing and will be noted as a follow-up (they are covered by admin Gate::before).

## Summary (Gate 3)

### What changed
- **3 migrations** created and verified (rollback + re-apply clean):
  - `add_profile_fields_to_members_table` — 10 nullable columns: `photo_path`, `blood_group` (enum), `caste`, `promotion_date`, `appointment`, `home_address`, `recruitment_type` (enum), `sport_event`, `other_notes`, `team_since`
  - `create_member_legacy_achievements_table` — `period` (PRE/POST_RECRUITMENT), `level` (reuses tournament tier codes), competition data, `medal_type`, `sort_order`; composite index on `(org, member, period, level)`
  - `create_achievement_benefits_table` — polymorphic `benefitable_type/id`, `benefit_type` enum (NONE = confirmed no benefit vs null = not entered), promotion rank fields, cash amount, order reference; two indexes
- **2 new models**: `MemberLegacyAchievement` + `AchievementBenefit` (both Tenanted, HasFactory)
- **Member model**: 10 new fillable fields, 2 new date casts, `legacyAchievements()` HasMany
- **3 new/updated factories**: `MemberFactory` (+10 fields with realistic fake weights), `MemberLegacyAchievementFactory` (states: preRecruitment/postRecruitment/forMember), `AchievementBenefitFactory` (states: promotion/cashAward/none)
- **MemberResource**: all 10 new fields exposed, dates via `->toDateString()`
- **config/rbac.php**: `members.manageLegacyAchievements` + `members.manageBenefits` added; synced to DB (22 total permissions)
- **MemberPolicy**: `manageLegacyAchievements()` + `manageBenefits()` added
- PHPDoc generic annotations added to all relation methods across all changed models (PHPStan level 6 clean)

### Decisions
- `member_legacy_achievements.level` reuses the same enum codes as `tournament_tiers` (no new lookup table)
- `benefit_type = NONE` is an explicit enum value meaning "confirmed no benefit received" — absence of row means "data not yet entered"
- Photo upload endpoint deferred to P2B-T03 (separate controller + multipart handling)
- Explicit morph map registration deferred to P2B-T05 (when polymorphic relation is first queried)

### Tests added
- None in this PR (schema + models only; covered by P2B-T09)
