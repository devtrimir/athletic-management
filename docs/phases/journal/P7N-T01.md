## Summary (Gate 3)

### What changed
- Added Phase 7N documentation and task tracking for the single-name-field cleanup.
- Renamed client-entered domain columns in schema, models, requests, resources, services, reports, factories, seeders, tests, and React/Inertia pages to neutral fields (`name`, `full_name`, `father_name`, `alias`, `reason`, `caption`, `in_charge`).
- Added compatibility migration `2026_06_14_000001_rename_domain_name_columns_to_neutral_fields.php` for existing databases, including MySQL trigger recreation for neutral normalized fields and rollback to legacy column names.
- Converted reference CSV loaders for sports, districts, and units to single `name` columns.
- Collapsed client-entered domain UI form pairs from `Name (Hindi)` / `Name (English)` to one `Name` field.
- Preserved bilingual system-label fields for RBAC, ranks, designations, tournament tiers, report labels, translations, nav/module labels, and inline rank creation.

### Decisions
- Domain/client-entered data no longer stores separate Hindi/English values.
- System labels remain bilingual and continue to use `name_hi/name_en` or `label_hi/label_en`.
- Existing fresh migrations were aligned to the new neutral schema; the new compatibility migration handles already-migrated databases.
- Sport slug generation now uses `Str::slug($name)` with a stable `sport-` plus short hash fallback when the input cannot produce an ASCII slug.

### Tests added
- Updated existing migration, CRUD, API, report, factory, and seeder tests to the neutral domain-field contract.

### Deferred / follow-ups
- `php artisan migrate:fresh --seed --env=testing --no-interaction` could not be completed in the sandbox because local MySQL access to `127.0.0.1:3306` was blocked; escalation was requested and declined.
- `npm run types:check` still reports pre-existing strict TypeScript debt unrelated to the rename after cleanup-specific duplicate-property errors were removed.
- A dedicated rollback verification against MySQL should be run outside the sandbox before merge because SQLite skips MySQL trigger/function DDL.
