## Plan (Gate 1)

### Scope
Implement `App\Auth\Rbac` as a singleton service with `userRoles()`, `userPermissions()`, and `userHasPermission()`. All results cached in Redis per `(user_id, org_id)` with TTL 1h and an in-process memo array for within-request deduplication. `invalidate()` flushes both layers. Register as singleton in `AppServiceProvider`.

### Schema / endpoints / pages
- No new schema. Queries `roles` JOIN `user_role` and `permissions` JOIN `role_permission`.

### Risk + mitigation
- **Risk:** Cache invalidation misses could serve stale RBAC data.
  **Mitigation:** In-process memo keyed by `(userId, orgId)` is cleared on `invalidate()`; Redis key also cleared. TTL of 1h is worst-case for stale data after a crash.
- **Risk:** Composite-key pivot `UserRole` model delete generates `WHERE id = null`.
  **Mitigation:** Always use query-level delete in the service and trait; never `$model->delete()` on composite-key pivots.

## Summary (Gate 3)

### What changed
- `app/Auth/Rbac.php` — singleton service:
  - `userRoles(User, int $orgId)` → queries `roles` JOIN `user_role WHERE user_id + organization_id`, Redis-cached + in-process memo
  - `userPermissions(User, int $orgId)` → queries `permissions` JOIN `role_permission WHERE role_id IN userRoles`, cached
  - `userHasPermission(User, string $code, ?int $orgId = null)` — uses `user->organization_id` when `$orgId` null
  - `invalidate(int $userId, int $orgId)` — deletes Redis keys + clears memo entry
  - Cache key pattern: `rbac:{roles|permissions}:{userId}:{orgId}`, TTL 3600
- `app/Providers/AppServiceProvider.php` — `$this->app->singleton(Rbac::class)` in `register()`
- `tests/Feature/RbacServiceTest.php` — 7 tests: userRoles, userPermissions, hasPermission true/false/org-fallback, memo identity, invalidation clears memo

### Decisions
- **In-process memo array:** A within-request cache prevents multiple `Cache::get()` round-trips for repeated permission checks in the same request (e.g., checking `can('members.view')` in middleware and then in a policy). Cleared on `invalidate()`.
- **`?int $orgId = null` on `userHasPermission`:** Convenience for callers that already have `$user->organization_id` as the context; avoids passing it on every `Gate::check()` call.
- **Singleton registration in `register()` not `boot()`:** Pure construction dependency; no other services needed.
