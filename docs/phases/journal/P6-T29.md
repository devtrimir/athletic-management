## Plan (Gate 1)

### Scope
Follow-up to P6-T28. The import job "fails" once then retries and completes, but the browser
never receives updates, and the import modal stays on the "file selected" state. User request:
row-wise live sync — the file's rows (PNO, name) appear in the same modal with a checkmark as
each row is processed, streamed over Reverb (no polling), plus fix the silent-notification bug.

### Boost MCP research (mandatory)
- `search-docs` packages=[laravel/framework, laravel/reverb, inertiajs/inertia-laravel] queries=["broadcasting events reverb queued job ShouldBroadcastNow", "inertia flash data shared props", "broadcasting private channel authorization"] → `ShouldBroadcastNow` broadcasts synchronously (correct for ordered per-row events); Inertia v3 flash data is delivered via the `flash` shared prop AND the `inertia:flash` client event; private channel auth via routes/channels.php (already in place for `organization.{id}`).
- Skills consulted: `member-module-structure`.

**Doc drift found:** `HandleInertiaRequests` still shares a dead `flash.import_result` key (the sync import flow it served was removed in P6-T28) — replaced with `flash.import_id` in this task.

### Files to touch
- `config/broadcasting.php` — reverb connection reads new `REVERB_INTERNAL_*` envs (server-side publish goes direct to `http://127.0.0.1:8080`, browser keeps `wss://reverb.test`)
- `.env`, `.env.example` — add `REVERB_INTERNAL_HOST/PORT/SCHEME`
- `app/Events/MemberImportRowProcessed.php` — new per-row broadcast event
- `app/Imports/MembersImport.php` — optional progress closure; emits per-row outcomes (failed during validation, created/updated/skipped during apply, skipped for dedupe-dropped rows)
- `app/Jobs/ProcessMemberImportJob.php` — non-fatal broadcasts (try/catch + Log::warning), drop `attempts() > 1` guard, wire progress closure
- `app/Http/Controllers/MemberImportController.php` — flash `import_id`
- `app/Http/Middleware/HandleInertiaRequests.php` + `resources/js/types/global.d.ts` — share `flash.import_id` (replacing dead `import_result`)
- `resources/js/components/members/member-import-dialog.tsx` — new extracted dialog with live row list
- `resources/js/pages/members/index.tsx` — use the dialog, hold import session state, consume row/finished events
- `tests/Feature/ProcessMemberImportJobTest.php`, `tests/Feature/MemberImportTest.php` — new coverage

### Schema / endpoints / pages
- No migration. No new route. Event: `MemberImportRowProcessed` on private `organization.{id}`.

### Risk + mitigation
- **Risk:** broadcast transport error fails the job (observed: cURL error 60 flipped a COMPLETED import to FAILED and swallowed the notification via the retry guard).
  **Mitigation:** server publishes over plain HTTP to loopback Reverb; every `broadcast()` wrapped in try/catch so transport errors can never affect import status; retry guard removed.
- **Risk:** per-row broadcasts for very large files add overhead.
  **Mitigation:** acceptable at roster-scale sizes (sync HTTP publishes to local Reverb, ~1–3 ms each); batching documented as follow-up.

### Test plan
- Pest Feature (`ProcessMemberImportJobTest`): row events fire per row with correct result/row/pno; finished event still fires; broadcast transport failure (dead reverb port) does not fail the job nor flip import status.
- Pest Feature (`MemberImportTest`): existing cases pass unchanged (progress param optional); channel auth for the new event name.
- Manual e2e: restart `queue:work` (env cache), upload template, watch rows tick in modal.

## Summary (Gate 3)

### What changed
- `config/broadcasting.php` — reverb connection now publishes via `REVERB_INTERNAL_HOST/PORT/SCHEME` (defaulting to the public `REVERB_*` values), so server-side events go straight to `http://127.0.0.1:8080` while browsers keep `wss://reverb.test`. This is the permanent fix for the `cURL error 60` job failures (the queue worker published over TLS to a cert-less loopback address).
- `.env` / `.env.example` — `REVERB_HOST` restored to `reverb.test` (user had pointed it at `127.0.0.1`, which caused the error-60 loop); new documented `REVERB_INTERNAL_*` vars.
- `app/Events/MemberImportRowProcessed.php` — new `ShouldBroadcastNow` event on `organization.{id}` with `{import_id, row, pno, name, result, errors, processed}`.
- `app/Imports/MembersImport.php` — optional 3rd constructor param: progress closure. Emits `failed` during validation, `created`/`updated`/`skipped` per applied row, and `skipped` for in-file duplicates superseded by a later row (every data row now gets an outcome; summary counts unchanged). Dedupe rewrite tracks kept indexes — apply order (PNO group, then name group) preserved so member-code assignment is unchanged.
- `app/Jobs/ProcessMemberImportJob.php` — all broadcasts wrapped in `publishSafely()` (try/catch → `Log::warning`): a transport error can never fail the job or flip a COMPLETED import to FAILED. The `attempts() > 1` guard moved from the finished event to the row-progress callback: a legitimate retry still notifies subscribers of the final outcome (no silent hangs) but doesn't replay row events (no duplicated checkmarks). User's uncommitted file-deletion placement (delete on success / in `failed()`) incorporated.
- `app/Http/Controllers/MemberImportController.php` — `store()` flashes `import_id` alongside the toast so the dialog can correlate events.
- `app/Http/Middleware/HandleInertiaRequests.php` + `resources/js/types/global.d.ts` — share `flash.import_id`; removed the dead `import_result` key (sync-flow leftover).
- `resources/js/components/members/member-import-dialog.tsx` — new dialog (extracted from the 1600-line index page): file view → on submit switches to a live row list (spinner → green check for created/updated, amber minus for skipped, red X with the error for failed), "N rows processed" counter, auto-scroll; `MemberImportFinished` for the active session renders an in-dialog summary (counts / failure box, error-report download, Done). Closing mid-import keeps streaming ("Run in background"); reopening resumes. Finished events for *other* imports keep the global toast + table reload.
- `resources/js/pages/members/index.tsx` — old inline dialog + `ImportFinishedListener` removed; renders `MemberImportDialog`.

### Decisions
- **Guard moved, not removed (deviation from approved plan):** the plan said remove the `attempts() > 1` guard; instead it now guards only the row-event replay, because a retry after a real crash must still deliver the finished notification — the original silent-hang scenario is fixed by making broadcasts non-fatal, not by muting them.
- **Per-row broadcast, no batching:** roster-scale files complete in well under a second of publish overhead; batching documented as a follow-up if files reach thousands of rows.
- **Row events filtered client-side by `import_id`:** the org channel is shared; the flashed `import_id` from the store redirect is the correlation key. Same-file re-upload reuses the import record (same id) — the dialog starts a fresh session, so old events with the same id are ignored via the `status !== 'importing'` filter.

### Tests added
- `tests/Feature/ProcessMemberImportJobTest.php` — per-row outcomes broadcast with correct row/pno/result/processed order; transport failure (dead reverb port) leaves the import COMPLETED and logs a warning; retrying job still notifies subscribers (replaced the old "notifies once" guard test).
- `tests/Feature/MemberImportQueueTest.php` / `MemberImportTest.php` — flash assertions updated for the new `import_id` key.

### Deferred / follow-ups
- Batch row events if imports ever reach thousands of rows.
- The user's queue worker must be restarted to pick up `REVERB_INTERNAL_*` (env is cached at worker start) — user action.
