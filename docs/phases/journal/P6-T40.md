## Plan (Gate 1)

### Scope
Rework "Playing career achievements" so that for a coach **linked to a member** (`coaches.member_id`) the section is read-only and derived from the member's real tournament achievements (event-linked: tournament, event, date, medal, **Team/Individual badge**) — not free-form entry. Free-form `coach_playing_achievements` CRUD remains only as a **legacy fallback** for coaches with no member link. User: "as a player, playing career achievement is not free text — it's a team medal or individual medal; read the full tournament module and review."

### Research (agent-17, 2026-09-05)
- Real achievements chain: `tournaments` → `events` (`event_type` enum individual|team) → `participations` (member_id nullable, team_id nullable, lineup_member_ids json) → `achievements` (medal_type GOLD/SILVER/BRONZE/MERIT, position).
- Team vs individual is derivable: `events.event_type` / participation `team_id`. The member achievements payload (`MemberProfileData::achievementsPayload` :381-446) does NOT expose this flag; the member events tab does (`team: {...} | null`, `event_type`).
- Member achievements projection: `member_id = X OR team_id IN (member's TeamMember teams)` (:391-406). Mirror this for the linked member.
- These rows live in `achievements`, so they already count in player-era tallies — correct; on the coach profile they are display-only and remain separate from the coached-team summary (`coachAchievements`) and promotions evidence.
- `coaches.member_id` is not settable in the UI yet (conversion flow = parked P6-T41) — for this task, tests set the link directly via factory/model.

### Design
- `CoachProfileData::playingAchievementsPayload()`:
  - Coach with member link → `source: 'member'`, read-only records derived from the linked member's achievements (same query shape as member payload), each record carrying: medal_type, position, session, tournament (name/tier/dates/venue), event name, **event_kind: 'team'|'individual'** (from event.event_type, fallback participation team_id).
  - Coach without link → `source: 'legacy'`, existing manual records (unchanged CRUD), UI shows a "Legacy" badge on the section.
  - Payload exposes whether the coach is linked (`linked_member` presence) so the UI can gate the add/edit dialog.
- Print preview + quick-view: render the derived records (with Team/Individual badge) for linked coaches; legacy records unchanged.
- UI (`playing-achievements-section.tsx`): linked → read-only list with Team/Individual badge, no add/edit; unlinked → existing CRUD with "Legacy" label.
- Translations: new keys in en.json AND hi.json ("Team", "Individual", "Legacy", badge labels, read-only note).
- Tests: derived payload for linked coach (medal, event, team/individual flag), legacy payload for unlinked, print + preview API payloads, no writes possible for linked (no store needed — endpoint still exists but UI hidden; keep backend unchanged for legacy).

### Risk + mitigation
- **Risk:** linked coach's derived rows double-shown as "coached" achievements. **Mitigation:** separate payload keys already; coached summary untouched — regression test.
- **Risk:** lineup-only members (lineup_member_ids without team_members row) missing from projection. **Mitigation:** mirror member-module behavior exactly (team_members based); note as known limitation, same as member profile.

## Summary (Gate 3) — fill after implementation

### What changed
- `CoachProfileData::playingAchievementsPayload()` branches by link: `source 'member'` (read-only, derived via mirrored member-achievements query) | `source 'legacy'` (free-form CRUD); `linked_member {id, member_code, full_name}` on both; `shell()` eager-loads member.

- UI section: linked = read-only rows (medal, tournament, event, Team/Individual badge, date, venue, tier, position) + derived note; unlinked = CRUD + Legacy badge.
- Print preview + quick-view (body + buildPrintHtml) render both shapes.
- en.json + hi.json: new keys both locales ("Team", "Individual", "Legacy", "Kind", "Tournament", notes/empty-state).

### Decisions
- `achieved_on` = tournament date_from (matches member payload).
- No writes to `coach_playing_achievements` for linked coaches; legacy table read only when unlinked.
- Known limitation (mirrors member module): lineup-only players (lineup_member_ids without team_members row) not projected.
