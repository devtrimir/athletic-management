## Plan (Gate 1)

### Scope
User rule: "when adding a participant even if it was individual, team_id should be stored — a member plays through their team; without a team no member participates in any event." Auto-resolve and persist `participations.team_id` for individual-event participations from the member's active team membership in that session. Also fixes the reported gap: individual medals never reached coach achievements (they require `team_id` + session match).

### Design
1. **Resolution rule:** when creating an individual participation, look up the member's `team_members` rows for that session with `left_on IS NULL`; pick the team whose sport matches the event's sport, else the single membership, else earliest joined. None → null (unchanged).
2. **Entry points:** `EventParticipantController::store` (:30-54 — currently forces team_id null for individual events), `MemberAchievementContextController::store` (:96-115), API `Api/V1/MemberAchievementsController` if it creates participations. Add a small resolver (service or private method) reused by all.
3. **Semantic audit — `team_id NOT NULL` no longer means "team medal":** classification must use `events.event_type` instead. Audit consumers: `MedalTallyReport::runTeams()`, `TournamentProfileData` (participants/medal stats, CONCAT 'team:'/'event:' grouping :320), `CoachProfileData::achievementsPayload` (now correctly picks up individual medals — desired), dashboards, exports. Adjust any place that inferred team-ness from `team_id` to use `event.event_type`.
4. **Backfill migration:** idempotent data migration setting `team_id` on existing individual participations where resolvable (member has active membership in that session; same sport-match rule; ambiguity → earliest joined membership). Guard with driver-safe SQL or a chunked Eloquent pass.
5. **Tests:** participation store auto-fills team_id for individual events; coach achievements tab now includes the individual medal (window rules still apply); team-medal classification in tallies unchanged (team medal only from team events); backfill migration verified on scratch DB only (never dev DB).

### Risk + mitigation
- Multi-team memberships in one session: sport-match rule then earliest-joined fallback; documented.
- Tally misclassification: audit + tests for medal-by-team reports with an individual medal carrying team_id.

Implemented:

- `EventParticipantController::store` — individual events now resolve+persist `team_id` instead of forcing null.
- `MemberAchievementContextController::store` — falls back to the resolver when the context-based team guess is ambiguous/absent for individual events.
- `Api/V1/MemberAchievementsController` audited: read-only, no participation creation — no change needed.
- Semantic audit — `team_id NOT NULL` no longer implies "team medal": `TournamentProfileData` now scopes `teams_count` (overview + per-event) and single/team participant splits by `events.event_type`; medal previews only expand lineups for team events. `MedalTallyReport::runTeams()`, `MedalsDetailReport`, `TournamentController` summaries, and `GenerateMedalsReportExportJob` already classified by `event_type` — no change. `MemberProfileData` team_achievements mapping already guarded by `event_type === 'team'`.

- Tests: resolver unit tests; backfill idempotency test; store autofill (sport-match two-team case; ambiguity fallback; unresolved → null); end-to-end coach achievements tests (individual medal included within assignment window, excluded when assigned after tournament date); team tally ignores individual medals carrying a team_id; `TournamentProfileTabsTest` overview setup updated to a real team event (old setup relied on team_id-presence semantics).
