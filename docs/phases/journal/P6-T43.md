## Plan (Gate 1)

### Scope
User: "date picker has issues — direct typing takes weird dates; fix the main component so it's resolved globally." Shared component `resources/js/components/date-picker.tsx` is used in 23 places.

### Root cause
1. `displayDateValue(value)` re-parsed the half-typed text on every keystroke via lenient `new Date(value)` (e.g. typing `12/05/202` → year 0202 on screen).
2. `normalizeTypedDate` ran date-fns v4 lenient parsing live, committing partial parses (e.g. `12/05/20` → year 0020).
3. Controlled input displayed a derived value, so the text under the cursor was rewritten mid-typing.

### Fix
- `parseDateValue`: canonical `yyyy-MM-dd` only (parseISO); lenient fallback removed.
- New `strictParseTypedDate`: regex-gated full forms only (`yyyy-MM-dd`, `dd/MM/yyyy`, `dd-MM-yyyy`, compact `ddmmyyyy`), calendar overflow rejected (31/02 rolls to March → invalid).
- Local `draft` state while typing: input shows the raw draft; only fully-formed dates commit to `onChange` live; partial input never touches form state.
- Blur: empty → clear; valid → commit (clamped to min/max as before); invalid → revert display to last committed value (server validation flags on submit).
- Calendar select path unchanged; clear button also resets draft.
