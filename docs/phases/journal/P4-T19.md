### Schema / endpoints / pages

### Risk + mitigation
- **Risk:** `CloneTeamDialog` member/coach list relies on `members` + `coaches` deferred props — list may be empty on first render
- **Mitigation:** Show skeleton in dialog while deferred props resolve; disable "Clone" button until loaded
- **Risk:** `⌘D` conflicts with browser bookmark shortcut in some contexts
- **Mitigation:** `e.preventDefault()` in the keydown handler; shortcut only fires when not inside an input

### Test plan
- No Vitest planned (Dialog components are interaction-heavy; covered by manual + future Pest Browser)
- Verify bilingual strings compile (no missing hi.json keys)

### AddMemberDialog spec
- Trigger: `<Button>` in Players tab header + `useEffect` keydown `(meta||ctrl) + shift + M`
- `Dialog` controlled by `open` state
- Inside: `MemberPicker` (existing) + filter pills for Unit, Category (GD/SKILLED), Level passed as `extraFilters`
- Below picker: Session `Select` (default = team session) + Role `Select` (PLAYER/CAPTAIN/RESERVE)
- Submit via `useForm.post(storeTeamMember.url(team))`
- On error from backend: show error inline inside dialog (not toast)
- On success: close dialog + reset form

### AddCoachDialog spec
- Trigger: `<Button>` in Coaches tab header + `(meta||ctrl) + shift + H`
- `CoachPicker` (existing) + NIS Certified toggle filter pill
- Session + Role (HEAD/ASSISTANT) selectors
- Same error/success handling

### CloneTeamDialog spec
- Trigger: "Clone to session…" `<Button>` in page header + `(meta||ctrl) + D`
- Section 1: Target session `Select` (excludes current session)
- Section 2: Players checklist — rows from `members` deferred prop (name, PNO, role badge) + Select all / None
- Section 3: Coaches checklist — rows from `coaches` deferred prop + Select all / None
- Warning note: "Players or coaches already in another team for the chosen session will be skipped."
- Submit: `useForm.post(cloneTeam.url(team))` with `{ session_id, member_ids[], coach_ids[] }`

### Filter pills spec
- Players tab: Session pill (SearchableOptionList from sessions), Role pill (OptionList: PLAYER/CAPTAIN/RESERVE)
- Coaches tab: Session pill, Role pill (HEAD/ASSISTANT)
- Client-side filtering on already-loaded deferred data
- "Clear filters" ghost button when any filter active; result count line

- `useForm` removed from `show.tsx` import (all form logic moved to Dialog components).

## Revision 1 — 2026-06-13

**Requested by user:** Make the add/remove member flow simpler and safer: search only active eligible players, support selecting many players, confirm removal, add undo, and make `joined_on` / `left_on` editable.

**What changed:**
- `AddMemberDialog` now hides the session selector, uses the team session as authoritative, filters search by `available_for_team_id`, defaults to active eligible candidates, supports multi-select chips, applies one role to the batch, and accepts `joined_on`.
- `teams/show.tsx` now shows `joined_on` and `left_on` columns on the Players tab.
- Added compact membership edit dialog for `role`, `joined_on`, and `left_on`.
- Single and bulk member removal now capture row data and show an Undo toast that re-adds removed members with original role/date data.
- `resources/lang/hi.json` includes the new dialog, undo, validation, and eligibility strings.

**Why:**
- The old add flow exposed session/status decisions that should be implicit from the team and business rule.
- Users should see fewer irrelevant search results and be able to add/remove many members without repeated work.
- Membership dates are operational data and need to be visible/editable from the team roster.
