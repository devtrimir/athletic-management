## Plan (Gate 1)

### Scope
Create 7 Policy classes (Member, Coach, Team, Tournament, Import, Report, Settings) whose methods delegate exclusively to `$user->can('permission.code')`. No role names are hard-coded. No manual registration — Laravel 13 auto-discovers policies by the `ModelPolicy` convention.

### Boost MCP research (mandatory)
- `search-docs` packages=[laravel/framework] queries=["policy authorization methods", "policy registration", "gate policy auto-discovery"] → Laravel 13 auto-discovers `App\Policies\{Model}Policy` without manual registration. `policy before()` is not needed — `Gate::before` in `AuthServiceProvider` already handles the admin bypass globally (per docs: "The `before` method will not be called if the class doesn't contain a matching ability method" — our `Gate::before` fires before any policy, covering admin bypass universally).
- Skills consulted: `laravel-best-practices`, `pest-testing`

### Risk + mitigation
- **Risk:** Models (Member, Coach, Team etc.) don't exist yet — policy auto-discovery will silently skip them until the models are created.
  **Mitigation:** Tests call policy methods directly (no model binding required for stubs). Auto-discovery will wire up automatically when models are added in later phases.

### Test plan
- Pest Feature (dataset-driven):
  - For each policy+method: user WITH the permission → returns `true`
  - For each policy+method: user WITHOUT the permission → returns `false`
  - Use a single dataset covering representative methods from each policy
