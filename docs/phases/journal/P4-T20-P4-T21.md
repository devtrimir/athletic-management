## Summary

### What changed
- Added `source`, `batch_uuid`, and `metadata` to `team_member_movements` for manual/carry-forward/backfill provenance.
- Added `TeamRosterService` to centralize current add, audited remove, carry-forward, and historical backfill behavior.
- Added `POST /teams/{team}/members/backfill/preview` and `POST /teams/{team}/members/backfill`.
- Added historical member-search mode so backfill can find inactive members without weakening normal team availability search.
- Updated Team Show with audited removal, old-roster backfill, removed-roster visibility, and movement source/reason display.
- Updated stale docs to stable-team/session-roster language.

### Decisions
- **Manual backfill first:** builds the safe preview/apply path now; full Excel import can reuse the service later.
- **Inactive allowed only in backfill:** normal add stays strict to avoid accidental current roster pollution.
- **Sport eligibility always required:** old roster data must still match the member's playable sports.
- **Blocked rows skipped on apply:** preview makes conflicts visible; apply writes only ready/warning rows.

### Tests added
- Current remove requires `left_on` and reason and records `REMOVED`.
- Bulk remove records the same audit details for every row.
- Historical backfill allows inactive playable members with warnings.
- Historical backfill blocks missing sport and same-sport active conflicts.
- Backfill with `left_on` records both `ADDED` and `REMOVED`.
- Backfill does not duplicate already recorded roster rows.
- Historical member search includes inactive playable members only when requested.
