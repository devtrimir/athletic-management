## Plan (Gate 1)

### Scope
User clarification (2026-09-05): playing achievements are **standalone records with event-shaped structure but NO hard FKs to live tournament tables** — the coach's playing past may involve tournaments not in the system, and records must survive independent of live data and stay out of all tallies. Event type (team/individual) is a **real form field** (stored as a column), not derived. No import/copy feature now (client doesn't need it), but the table must be **structured for a future copy-from-member-achievements feature**.

### Design (revised)
- New migration `2026_09_05_130000_add_event_structure_to_coach_playing_achievements_table.php` (idempotent, hasColumn-guarded):
  - `event_type` enum `team|individual` NULLABLE (legacy rows stay null; new entries require it via validation)
  - `source_achievement_id` nullable FK → `achievements.id`, **nullOnDelete** — provenance only: set later when a record is copied from a member's real achievement; NEVER joined from tally queries. Future copy feature (P6-T41 follow-up) sets this and the UI can badge "Copied from member record".
- Model: fillables + docblock; relations `sourceAchievement()` BelongsTo (for future use).
- Form requests: `event_type` required `in:team,individual` (update: `sometimes`).
- Form UI: Team/Individual select added to the dialog (required); records list shows Team/Individual badge when `event_type` set, Legacy badge otherwise (existing behavior).
- Payload (`CoachProfileData::playingAchievementsPayload` + `CoachPreviewController`): expose `event_type` (+ `source_achievement_id` for future badge use); keep everything else unchanged.
- Print preview + quick view: kind column shows for rows with event_type.
- Translations: new keys en+hi ("Team", "Individual" likely already exist after T40 — reuse; "Event type" check; "Individual event"/"Team event" if needed).

### Explicitly OUT of scope
- No import/copy action, no UI for provenance badge beyond payload field, no FK to tournaments/events.

### Test plan
- Store/update with event_type persisted; validation rejects missing/invalid event_type (update: `sometimes`).
- Payload exposes `event_type`; legacy rows (null) render unchanged.
- Preview API + print payload include the field.
- Tally isolation regression unchanged (separate table).
