## Plan (Gate 1)

### Scope
On `/coaches/{coach}/promotions`, the promotion modal does not pre-select the coach's current rank, validation allows near-blank records to be saved, and the audit log labels both promotions and cash rewards as "Promotion". This task fixes all three issues and verifies the related Hindi translation keys.

### Boost MCP research
- `search-docs` packages=["laravel/framework"] queries=["form request validation", "nullable sometimes rules"] → standard `nullable|date` + custom `withValidator` hooks are the right tool for cross-field rules.
- Skills consulted: `laravel-best-practices`, `pest-testing`, `inertia-react-development`.

### Files to touch
- `resources/js/pages/coaches/show.tsx` — pre-fill `from_rank`, add client-side validation, keep modal open on errors.
- `app/Http/Requests/Coaches/StoreCoachPromotionRequest.php` — require `promotion_date` + `to_rank` for promotions, `cash_reward_amount` for rewards.
- `app/Http/Requests/Coaches/UpdateCoachPromotionRequest.php` — same per-mode tightening.
- `app/Services/AuditLogBuilder.php` — dynamic subject for `CoachPromotion` logs (Promotion vs Reward).
- `resources/lang/hi.json` — add/verify keys touched by this change.
- `tests/Feature/CoachPromotionControllerTest.php` — add validation + audit-subject coverage.

### Schema / endpoints / pages
- No migrations.
- Endpoints affected: `POST /coaches/{coach}/promotions`, `PATCH /coaches/{coach}/promotions/{promotion}`.
- Page affected: `/coaches/{coach}/promotions`.

### Risk + mitigation
- **Risk:** Tightening validation could break existing promotion/reward edit flows.
  **Mitigation:** Update tests cover both create and edit paths; rules only add requirements per mode, evidence validation remains unchanged.
- **Risk:** Audit subject change could affect changelog tab display.
  **Mitigation:** Subject stays in the same timeline; only the human-readable label changes based on record type.

### Test plan
- Pest Feature: promotion create fails without `promotion_date` / `to_rank`; reward create fails without `cash_reward_amount`; edit preserves existing values; audit log shows correct subject.

## Summary (Gate 3)

### What changed
- `resources/js/pages/coaches/show.tsx`
  - Added `rank_master` to the `Coach` type so the dialog can read the coach's current rank.
  - `resetPromotionForm()` and `openEditPromotionDialog()` now pre-fill `from_rank` with `coach.rank_master?.code` when no explicit value exists.
  - Added `isPromotionFormValid()`: promotion mode requires `promotion_date` + `to_rank`; reward mode requires `cash_reward_amount`.
  - Save button is disabled until the mode-specific required fields are filled.
  - Added an `onError` callback so the modal stays open when server validation fails.
- `app/Http/Requests/Coaches/StoreCoachPromotionRequest.php` — per-mode `withValidator` rules now require `promotion_date` and `to_rank` for promotion records and `cash_reward_amount` for reward records.
- `app/Http/Requests/Coaches/UpdateCoachPromotionRequest.php` — same tightening for edits, using existing record values as defaults so emptying a required field is rejected.
- `app/Services/AuditLogBuilder.php` — added `coachPromotionSubject()` so `CoachPromotion` logs are labeled **Promotion**, **Reward**, or **Promotion + Reward** based on the diff fields.
- `resources/lang/hi.json` + `resources/lang/en.json` — added Hindi and English strings for the new backend validation messages.
- `tests/Feature/CoachPromotionControllerTest.php` — new test file covering permission gating, promotion/reward validation, happy-path persistence, and audit-log subject resolution.
- `tests/Feature/CoachControllerTest.php` — updated the existing promotion+reward audit assertion to expect the new **Promotion + Reward** subject.

### Decisions
- **Infer mode from submitted fields on the backend** rather than adding a hidden `mode` field, so validation stays honest even if the frontend is bypassed.
- **Keep `from_rank` nullable in the rules** but default it to the coach's current rank both in the UI and in the controller, preserving the existing fallback behavior.
- **Dynamic audit subject lives in `AuditLogBuilder`** rather than a model accessor so the change applies only to the audit timeline and does not affect other consumers of `CoachPromotion`.

### Tests added
- `tests/Feature/CoachPromotionControllerTest.php` (8 tests): permission gate, promotion/reward create validation, promotion/reward persistence, edit validation, audit subject.
- Updated `tests/Feature/CoachControllerTest.php` existing audit assertion.

### Deferred / follow-ups
- Pre-existing failures in `CoachControllerTest` for coach index counts and print-page English text assertions are unrelated to this change (they fail on the current branch before these edits). They likely need a separate cleanup task for Hindi-locale test fixtures or print-page label assertions.
