## Plan (Gate 1)

### Scope
"Pest: audit log fires on every reference-data write."
Proves that every HTTP write (store/update/destroy) to the 5 reference-data resources
(Sport, SportSession, Unit, District, TournamentTier) produces an `audit_logs` row with
the correct `entity`, `entity_id`, `action`, and `user_id` fields.
The existing `AuditLoggerTest.php` covers direct Eloquent writes; this task covers the
full HTTP → controller → Eloquent → observer → AuditLog pipeline.

- `search-docs` packages=[pest] queries=["pest datasets", "pest feature test"]
  → Use Pest datasets to avoid 15 near-identical test bodies; dataset drives resource class, route names, and valid payloads.
- Existing code reviewed: `app/Services/AuditLogger.php`, `app/Observers/AuditObserver.php`, `app/Models/AuditLog.php`
- All 5 reference models have `#[ObservedBy([AuditObserver::class])]` confirmed.
- Routes confirmed via `php artisan route:list --path=settings`: `sports.*`, `sessions.*`, `units.*`, `districts.*`, `tournament-tiers.*`
- Skills consulted: `pest-testing/SKILL.md`

**Doc drift found:** None.

### Files to touch
- `tests/Feature/ReferenceDataAuditTest.php` — new: dataset-driven test covering store/update/destroy for all 5 resources

### Risk + mitigation
- **Risk:** `Sport`, `SportSession`, `Unit` now require an authenticated user due to the `Tenanted` global scope (added P1-T35). Factories + `actingAs` with same-org user are needed.
  **Mitigation:** Use the same admin setup pattern from `RbacMatrixTest.php` — create an org, an admin user, and create model fixtures with matching `organization_id`.
- **Risk:** `District` and `TournamentTier` are global models (no `organization_id`) — no scope issue, but still need valid FK data.
  **Mitigation:** Create org + admin; District/TournamentTier don't need `organization_id`.

### Test plan
Single file `tests/Feature/ReferenceDataAuditTest.php` with three dataset-driven tests:

1. **store fires created log** — for each resource: POST valid data as admin → assert `AuditLog` row with `action=created`, correct `entity`/`entity_id`, `user_id=admin->id`
2. **update fires updated log with diff** — for each resource: PATCH field change as admin → assert `AuditLog` row with `action=updated`, `diff.old`/`diff.new` containing changed field
3. **destroy fires deleted log** — for each resource: DELETE as admin → assert `AuditLog` row with `action=deleted`

Datasets provide per-resource: model class, store route, store payload, update route (with model), update payload, destroy route, a changed-field key.
