### Schema / endpoints / pages
- Migration: `roles` — `id`, `organization_id` FK nullable (nullOnDelete), `code` string, `label` string, `is_system` boolean default false, timestamps; unique `(organization_id, code)`
- Migration: `permissions` — `id`, `code` string unique, `label` string, timestamps
- Migration: `role_permission` — composite PK `(role_id, permission_id)`, FKs cascadeOnDelete, no timestamps
- Migration: `user_role` — composite PK `(user_id, role_id, organization_id)`, FKs cascadeOnDelete, `assigned_by` nullable FK, `assigned_at` timestamp

### Risk + mitigation
- **Risk:** Composite-key pivot `delete()` on model instance generates `WHERE id = null`.
  **Mitigation:** Always use query-level `->where(...)->delete()` for pivot deletes; documented in `HasRoles` trait (P1-T11).

## Summary (Gate 3)

### What changed
- `database/migrations/2026_05_21_114447_create_roles_table.php` — `roles`: org-scoped (nullable), code+org unique index, `is_system` flag
- `database/migrations/2026_05_21_114447_create_permissions_table.php` — `permissions`: global (no org_id), `code` unique
- `database/migrations/2026_05_21_115058_create_role_permission_table.php` — composite PK, both FKs cascadeOnDelete, no timestamps
- `database/migrations/2026_05_21_115058_create_user_role_table.php` — composite PK `(user_id, role_id, organization_id)`, cascadeOnDelete, `assigned_by` nullable FK nullOnDelete, `assigned_at` useCurrent
- `app/Models/Role.php` — `#[Fillable(['organization_id','code','label','is_system'])]`, `HasFactory`
- `app/Models/Permission.php` — `#[Fillable(['code','label'])]`, `HasFactory`
- `app/Models/RolePermission.php` — `$table = 'role_permission'`, `$timestamps = false`, `#[Fillable(['role_id','permission_id'])]`; `booted()` saved/deleted observer calls `Rbac::invalidate()` per affected user
- `app/Models/UserRole.php` — `$table = 'user_role'`, `$timestamps = false`, `#[Fillable(['user_id','role_id','organization_id','assigned_by'])]`; `booted()` saved observer calls `Rbac::invalidate()`
- `database/factories/RoleFactory.php` — factory with `is_system: false`, `organization_id: null` default
- `database/factories/PermissionFactory.php` — unique `code` via sequence
- `tests/Feature/RbacSchemaTest.php` — columns and constraints on roles/permissions
- `tests/Feature/RolePivotsTest.php` — pivot table structure, factory-based record creation

### Decisions
- **`permissions` has no `organization_id`:** Permissions are global codes defined by the system; roles are org-scoped but draw from the same global permission pool.
- **`$timestamps = false` on pivots:** `role_permission` has no timestamps at all; `user_role` has only `assigned_at` (not the standard `created_at`/`updated_at` pair).
- **Composite PK on pivots (no surrogate `id`):** Prevents duplicate assignments at the DB level with zero extra index overhead.
