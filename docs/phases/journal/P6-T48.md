## Plan (Gate 1)

### Scope
The shared `ConfidentialDocumentPreview` modal was made full-viewport in P6-T34, but on desktop screens the underlying shadcn `DialogContent` default includes `sm:max-w-lg`, which overrides the intended `max-w-none` and constrains the modal to ~512 px. This task adds a responsive override so the modal uses the full available width at every breakpoint.

### Boost MCP research
- Not required: one-line Tailwind specificity fix on an existing shared component.
- Skills consulted: `tailwindcss-development`.

### Files to touch
- `resources/js/components/shared/confidential-document-preview.tsx` — add `sm:max-w-none` (or `!max-w-none`) to `DialogContent` className.

### Schema / endpoints / pages
- No new schema or endpoints.
- Affects every page using `ConfidentialDocumentPreview`:
  - Coach special achievements tab
  - Member special achievements tab
  - Coach show page
  - Sports calendar form
  - External coaching assignments form/show

### Risk + mitigation
- **Risk:** Modal becomes too wide on mobile.
  **Mitigation:** `w-screen` is already constrained by viewport; `sm:max-w-none` only removes the sm breakpoint max-width. The inner image uses `object-contain` and PDF iframe uses `w-full`, so content remains usable.

### Test plan
- Manual visual check on the reported URL `/coaches/1/special-achievements`.
- `npm run type-check` and `npm run build` to ensure no TS/build regressions.
- `npm run lint` to confirm formatting.

## Summary (Gate 3)

### What changed
- `resources/js/components/shared/confidential-document-preview.tsx` — `DialogContent` className now includes `sm:max-w-none !p-0` to override the default `sm:max-w-lg` and `p-6` from the shadcn base component, ensuring the modal fills the viewport width at all breakpoints.

### Decisions
- **Used `!p-0` and `sm:max-w-none`:** explicit `!important` utilities guarantee the overrides win against the shadcn defaults regardless of source order or future base-class changes.

## Revisions (Gate 4)

## Revision 1 — 2026-09-05
**Requested by user:** "what I can see some top and bottom space still not filling up can use that space too"
**What changed:** `resources/js/components/shared/confidential-document-preview.tsx` — added `max-h-dvh` and `!gap-0` to the `DialogContent` className to override the base class's `max-h-[90dvh]` and `gap-4`, removing the remaining top/bottom margins and internal spacing.
**Why:** The base shadcn `DialogContent` applies `max-h-[90dvh]` (caps height) and `gap-4` (adds flex gap) in addition to `sm:max-w-lg`. All three must be overridden for a true full-viewport modal.
