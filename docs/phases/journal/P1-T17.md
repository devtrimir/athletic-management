## Plan (Gate 1)

### Scope
Extend the existing `SetLocale` middleware stub (currently reads only from `session('locale', 'hi')`) to read `users.locale` first for authenticated requests. Guests continue to use the session fallback.

### Boost MCP research (mandatory)
- `search-docs` queries=["middleware locale app setLocale"] → confirmed `app()->setLocale()` is the correct call; no version-specific caveats in L13.
- Allowed locales: `['hi', 'en']` per `copilot-instructions.md`.

### Files to touch
| File | Change |
|---|---|
| `app/Http/Middleware/SetLocale.php` | modify — add user locale resolution |
| `tests/Feature/SetLocaleMiddlewareTest.php` | new |

### Resolution priority
1. `auth()->user()->locale` — authenticated user's stored preference
2. `session('locale')` — guest session switch via `LocaleController`
3. `'hi'` — hardcoded default

Any unrecognised value is normalised to `'hi'` (guards against stale data / injection).

### Risk + mitigation
- **Risk:** A future `/{locale}` route prefix (P2+) would override this middleware.
  **Mitigation:** The middleware fires before routing-level locale, so when route prefixes are added the order in `bootstrap/app.php` can be adjusted at that point. No changes needed now.

### Test plan
- Authenticated user with `locale = 'en'` → `app()->getLocale()` is `en`.
- Authenticated user with `locale = 'hi'` → `app()->getLocale()` is `hi`.
- Guest with `session locale = 'en'` → `app()->getLocale()` is `en`.
- Guest with no session → `app()->getLocale()` is `hi`.
- Value not in `['hi', 'en']` → normalised to `hi`.
