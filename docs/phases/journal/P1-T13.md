## Plan (Gate 1)

### Scope
Create two named route middlewares — `role` and `permission` — that each accept a pipe-delimited any-of argument list. Both abort 403 for authenticated users who fail the check. Register aliases in `bootstrap/app.php`.

### Boost MCP research (mandatory)
- `search-docs` packages=[laravel/framework] queries=["middleware registration bootstrap app.php", "custom middleware with parameters", "middleware aliases laravel 13", "abort 403"] → Laravel 13 uses `$middleware->alias([...])` in `bootstrap/app.php`; middleware parameters passed after `$next`; multi-param via comma-delimited string on route (pipe-split is our own convention within one param).
- Skills consulted: `laravel-best-practices`, `pest-testing`

**Doc drift found:** None.

### Files to touch
- `app/Http/Middleware/RequireRole.php` — new; any-of role check via `HasRoles::hasAnyRole`
- `app/Http/Middleware/RequirePermission.php` — new; any-of permission check via `Rbac::userHasPermission`
- `bootstrap/app.php` — register `role` + `permission` aliases
- `tests/Feature/RouteMiddlewaresTest.php` — new; Pest Feature tests

### Schema / endpoints / pages
None — middleware only.

### Risk + mitigation
- **Risk:** `organization_id` null on user (e.g., super-admin without org) causes Rbac to fail silently.
  **Mitigation:** Both middlewares check `$user->organization_id`; abort 403 if null (no org = no access).

### Test plan
- Pest Feature:
  - `role:` middleware passes when user has any of the required roles
  - `role:` middleware returns 403 when user has none of the required roles
  - `permission:` middleware passes when user has any of the required permissions
  - `permission:` middleware returns 403 when user has none
  - Unauthenticated user hits the `auth` middleware first — test that both middlewares are not called without auth (401 redirect)

## Summary (Gate 3) — fill after implementation

### What changed
- `app/Http/Middleware/RequireRole.php` — splits the `roles` param on `|`, calls `$user->hasAnyRole(codes, orgId)`, aborts 403 on fail. Also aborts 403 if user is null or has no `organization_id`.
- `app/Http/Middleware/RequirePermission.php` — splits the `permissions` param on `|`, calls `Rbac::userHasPermission` for each code, passes on any-true, aborts 403 otherwise.
- `bootstrap/app.php` — registers `role` and `permission` middleware aliases via `$middleware->alias([...])`.
- `tests/Feature/RouteMiddlewaresTest.php` — 6 tests across both middlewares.

### Decisions
- **Single string param + pipe split:** Laravel passes everything after `:` as one param. We `explode('|', $roles)` inside the middleware — consistent with how `spatie/laravel-permission` and similar packages handle any-of lists.
- **403 for no-user rather than redirect:** These middlewares are designed to sit *after* `auth` on real routes. Without `auth`, they return 403 (no user = no org = no access). The `auth` middleware owns the redirect responsibility.
- **`collect()->contains()` for any-of permission check:** Short-circuits on first match, avoids unnecessary Rbac cache hits for remaining codes.

### Tests added
- `tests/Feature/RouteMiddlewaresTest.php` — 6 tests:
  - `role:` passes for matching role
  - `role:` 403 for unmatched role
  - `permission:` passes for granted permission
  - `permission:` 403 for missing permission
  - Unauthenticated → 403 from both (auth middleware redirects before reaching these in production)
