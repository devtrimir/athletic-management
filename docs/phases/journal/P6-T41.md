## Plan (Gate 1)

### Scope
Build a "convert member" flow: a serving player who becomes a coach or team prabhari (incharge) is converted with auto-sync between the two roles, soft-delete-style lifecycle on the member side. User: "a player in future may be converted to coach or team prabhari — I want auto sync system, deleting the player as a soft-delete kind of feature."

### User decisions (2026-09-05)
1. **Member record: mark retired, keep record.** On conversion the member gets a terminal status (RETIRED, or a new `CONVERTED` status if clearer) + `member_status_history` entry; the existing `ChangeMemberStatus` action auto-closes open `team_members` rows. Record, history, and medals stay fully preserved in all tallies (tallies filter soft-delete only, not status). Conversion is reversible: restore status + unlink.
2. **Both targets in one task** — coach AND incharge (prabhari).
3. **Playing achievements:** event-derived for linked coaches (delivered separately in P6-T40); manual free-form entries remain only as a **legacy fallback** for coaches with no member link.
4. Sequencing: PR #192 (P6-T39) merges first; P6-T40 (playing achievements rework) builds on it; this task lands after.

### Research already done (agent-17, 2026-09-05)
- `coaches.member_id` nullable FK → members exists (`2026_05_24_084342:22`, `Coach::member()` :131) but is **not settable in the UI** (no rule in Store/UpdateCoachRequest, no picker in create/edit forms); used only for a `linked_member` export column. Legacy seeder/backfill set it by PNO.
- `incharges` table has **no member_id column** — must add nullable FK (new migration).
- Member statuses: `Member::STATUSES` ACTIVE/INACTIVE/RESIGNED/DISMISSED/DECEASED/RETIRED (+DOPING_DISQUALIFIED); `ChangeMemberStatus` (app/Actions/Members/ChangeMemberStatus.php:26-95) writes history + closes team memberships on non-ACTIVE.
- No existing convert flow anywhere; `external_coaching_assignments` links members acting as external coaches by member_id (parallel concept).

### Detailed design

**Backend — conversion action**
- `app/Actions/Members/ConvertMember.php` (or dedicated controller `MemberConversionController`):
  - Input: target role (`coach`|`incharge`), effective date, reason, optional role-specific fields.
  - Wrap in DB transaction:
    1. Create `Coach` (or `Incharge`) copying identity fields from member: full_name, pno, mobile, rank (rank_master_id), gender, dob, photo_path, posting unit/district.
    2. Set `coaches.member_id` = member id (or new `incharges.member_id`).
    3. Member status → RETIRED (or CONVERTED) via `ChangeMemberStatus` with reason "Converted to {role}".
  - Guard: PNO collision on target table (incharges.pno unique per org; coaches.pno?) — reject with clear error if the person already exists as coach/incharge.
  - Guard: idempotency — refuse if member already has a linked coach/incharge record.
- Reversal endpoint: restore member status (existing status flow) + `DELETE` link (set member_id null) — decide whether coach record is kept or soft-deleted; recommend keep + unlink so coach history isn't destroyed.
- RBAC: new permission `members.convert` (bilingual), policy method, audit-log wiring for both sides (member status change + coach/incharge creation).

**Frontend**
- Member profile (show page, likely status/actions area): "Convert to Coach / Prabhari" button (permission-gated) → dialog: target role select, effective date, reason; success toast + link to the new coach/incharge profile.
- Coach/incharge create forms: optionally add a member picker to link an existing member without conversion (fills fields via link) — decision: include, since `member_id` is otherwise unsettable in the UI.
- Coach/incharge profile: show "Converted from member {code}" chip linking to member record when member_id set.

**Migration**
- `incharges`: add nullable `member_id` FK → members (nullOnDelete, index).
- Optional: `CONVERTED` member status (only if RETIRED is deemed ambiguous — decide at implementation; RETIRED is acceptable per user decision).

**Tests (Pest Feature)**
- Convert to coach: creates linked coach with copied fields, member retired, memberships closed, audit entries.
- Convert to incharge: same incl. new member_id column.
- Guards: duplicate PNO rejected; already-converted member rejected; permission 403.
- Reversal: unlink + status restore.
- Playing-achievement auto-visibility: converted member's achievements appear on coach profile (integration with P6-T40 payload).

**Risks / mitigations**
- Tallies must not change on conversion — status is not filtered in reports (verified); add regression test asserting medal counts unchanged after conversion.
- Data divergence after conversion (member vs coach contact fields): one-way copy at conversion; thereafter independent (coach managed as coach). The member link remains the bridge for history/achievements only.
