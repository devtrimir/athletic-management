## Plan (Gate 1)

### Scope
Fix broken unique constraints on `team_members` and `coach_assignments` to enforce "one team per member/coach per session" across all teams. Add cross-session validation with bilingual errors to `TeamMemberController` and `TeamCoachController`. Add new `TeamCloneController` + `CloneTeamRequest` to duplicate a team (with selectable members/coaches) into a different session.

## Revision 1 — 2026-06-13

**Requested by user:** Change the member assignment rule from "one team per member per session" to "one team per member per sport per session"; allow same-session membership for different playable sports; ensure stale database constraints do not block the rule.

**What changed:**
- `TeamMemberController` now uses the route team's `session_id` and `sport_id`, requires `ACTIVE` members, requires `member_sport` eligibility, and blocks only same-session same-sport conflicts.
- `TeamCloneController` skips inactive, non-playable, and same-session same-sport conflicting members when copying rosters.
- `MemberSearchController` + `MemberSearchService` gained team-aware availability filters for active, playable, not-yet-assigned candidates.
- `2026_05_28_062227_fix_team_member_coach_unique_constraints.php` was corrected to avoid creating `(member_id, session_id)` uniqueness for `team_members`.
- `2026_06_13_082812_restore_team_member_team_member_unique_index.php` was added as a forward repair migration for databases that had already run the stale `(member_id, session_id)` unique index.

**Why:**
- The final business rule is not "one team per session"; it is "one team per sport per session".
- `sport_id` lives on `teams`, so the same-session same-sport rule is enforced in application logic; the database keeps only duplicate-in-same-team protection via `(team_id, member_id)`.
