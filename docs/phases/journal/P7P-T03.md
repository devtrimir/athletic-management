## Summary (Gate 3)

### What changed
- `app/Services/Reports/PlayerPerformanceReport.php` — added a ranking report adapter that reshapes `PlayerPointsService` member summaries into report rows with rank, medal buckets, counts, and total points
- `app/Http/Controllers/ReportController.php` — registered `player-performance-ranking`, validated optional `limit`, and routed execution through the new report service
- `resources/js/components/nav-reports.tsx` — added the report to the reports navigation
- `resources/lang/hi.json` — added the Hindi label for the new report
- `tests/Feature/Reports/PlayerPerformanceReportTest.php` — added focused coverage for ranking math, filters, org isolation, limit handling, and controller delivery
- `tests/Feature/ReportControllerTest.php` — updated the gallery/report-key expectations to include the new report

### Decisions
- **Reuse the generic report shell:** the backend ships a flat, table-friendly payload first so the report is usable before the richer frontend lands in `P7P-T04`.
- **Rank from member summaries:** the report consumes the scoring service's grouped member output, keeping the leaderboard consistent with the future member performance tab.
- **Permission setup follows shared helpers:** controller coverage uses the existing `rcUser('reports.view')` test helper so report auth stays aligned with the rest of the suite.

### Tests added
- `tests/Feature/Reports/PlayerPerformanceReportTest.php` — 5 focused feature tests
- `tests/Feature/ReportControllerTest.php` — updated existing report gallery coverage for the new key
