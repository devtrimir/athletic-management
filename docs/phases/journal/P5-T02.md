## Summary (Gate 3)

### What changed
- `database/migrations/2026_05_24_115536_create_events_table.php` — tournament_id FK with cascadeOnDelete, sport_id FK, enum gender_class, nullable discipline + weight_category
- `app/Models/Event.php` — HasFactory + Fillable + 2 relationships (tournament, sport) + PHPDoc; no Tenanted (no organization_id)
- `database/factories/EventFactory.php` — definition() with inline Tournament+Sport factories; forTournament() reuses tournament's sport_id or creates one in same org
- `tests/Feature/EventsMigrationTest.php` — 5 passing tests

### Decisions
- **No Tenanted on Event:** `events.organization_id` not in spec; multi-tenancy scoped through tournament. Access control enforced in TournamentPolicy in P5-T05.
- **Cascade via DB::table in test:** `Tournament` uses SoftDeletes + Tenanted scope — `forceDelete()` on the model instance would apply the tenant scope (org=0 without auth) and miss the row. Raw `DB::table` bypasses ORM to prove the DB-level cascade constraint.
