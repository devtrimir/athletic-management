## Summary (Gate 3)

### What changed
- `app/Providers/AuthServiceProvider.php` — single `Gate::before`:
  1. Returns `null` for users with no `organization_id` (guests / incomplete setup)
  2. Checks `Rbac::userRoles` for `is_system = true` AND `code = 'admin'`; returns `true` (bypass all checks) if admin
  3. Delegates to `Rbac::userHasPermission`; returns `true` if granted, `null` if not (Gate falls through → denies)
- `bootstrap/providers.php` — `AuthServiceProvider::class` added
- `tests/Feature/AuthServiceProviderTest.php` — 3 tests, 4 assertions

### Decisions
- **Single `Gate::before` instead of per-permission `Gate::define`:** The original plan required querying the `permissions` table at provider boot (to enumerate all codes for `Gate::define`). This breaks `RefreshDatabase` tests — migrations run in `setUp()`, after the app boots. The `Gate::before` approach is fully lazy: it executes only when an actual Gate check fires, well after migrations have run.
- **`null` returned for ungranted checks (not `false`):** Returning `false` from `Gate::before` would block all policies and all `Gate::define` calls registered by other providers. Returning `null` allows fall-through, which means policies defined in P1-T15 can still run independently.
