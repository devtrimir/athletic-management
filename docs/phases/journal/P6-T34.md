## Plan (Gate 1)

### Scope
Two small coach-module fixes:
1. **Document modal full view** — `ConfidentialDocumentPreview` currently renders at 96vw/90vh with padding, leaving space on all sides. Make it true full-screen (edge-to-edge). Shared component — change applies to all usages (member achievements, sports calendars, external coaching, coach certifications) for UI consistency.
2. **Posting XOR** — mirror the member module rule: a coach is posted at a unit OR a district, never both. Backend `prohibits` validation on `unit_id`/`district_id` + UI that clears/disables the other field + helper text + tests.

### Research
- `search-docs` not required (component restyle + standard `prohibits` rule already proven in member requests).
- Member precedent: `StoreMemberRequest.php:38-39` / `UpdateMemberRequest.php:39-40` (`prohibits:`), frontend clear+disable at `members/create.tsx:642-723`, tests at `MemberPostingAndRankTest.php:89-151`.
- DB directive: **never reset/roll back the dev DB** — scratch DB only; tests use in-memory sqlite anyway.

### Files to touch
- `resources/js/components/shared/confidential-document-preview.tsx` — full-screen dialog sizing
- `app/Http/Requests/Coaches/StoreCoachRequest.php` / `UpdateCoachRequest.php` — `prohibits` on unit_id/district_id
- `resources/js/pages/coaches/create.tsx` / `edit.tsx` — clear/disable the other combobox + helper text
- `tests/Feature/CoachControllerTest.php` — store/update reject-both cases

### Risk + mitigation
- **Risk:** full-screen modal on small screens. **Mitigation:** use `dvh` units; keep header/footer layout unchanged.
- **Risk:** existing coach rows that have both unit and district would fail *updates* that resubmit both. **Mitigation:** `prohibits` only fires when both present in the request; edit form sends one cleared, and data fix is out of scope (flag to user).

### Test plan
- Pest: store rejects both unit+district (errors on both keys), accepts unit-only / district-only; update same
- types:check + prettier on touched files
